\section{Attack Methodology, Execution Steps \& Direct Empirical Evidence}\label{sec:steps}

This section details the end-to-end attack methodology, the underlying protocol mechanics, the
associated timing sequences, and the direct empirical console logs captured during live testbed
executions.

\subsection{Phase 1: TCP SYN Port Scanning Methodology}
Standard TCP connections require a full three-way handshake (SYN $\to$ SYN/ACK $\to$ ACK), after
which application listeners log the session. Our scanner implements a half-open SYN scan: it
dispatches a raw Layer-2 SYN probe and evaluates the target kernel's immediate response:
\begin{itemize}
    \item \textbf{Open Port ($\text{SYN}=1, \text{ACK}=1$):} The target service is listening. The
    scanner records the port as \textsc{open}, ingests the frame's TTL, Window Size, and TCP Options
    as primary fingerprinting telemetry, and \hl{withholds the final ACK}. The connection remains
    unestablished and is never committed to application connection logs.
    \item \textbf{Closed Port ($\text{RST}=1$):} The destination host kernel rejects the connection.
    The scanner records the port as \textsc{closed} and harvests the RST packet's initial TTL,
    Window Size, and IP-ID for the \textbf{Closed-Port RST Fallback Pipeline}.
    \item \textbf{Filtered Port (No Reply / Drop):} A host-based or network firewall drops the SYN
    packet. The scanner waits for a configurable timeout interval ($t_{\text{timeout}} = 1.5$\,s)
    before classifying the port as \textsc{filtered}.
\end{itemize}

\subsection{Phase 2: Service Banner Grabbing Methodology}
Once open ports are catalogued, standard TCP stream connections are established to extract daemon
identity strings. Because application daemons behave differently, the grabber follows two distinct
operational paths:
\begin{itemize}
    \item \textbf{Passive Services (e.g., FTP):} The daemon emits an unsolicited greeting string
    immediately upon three-way handshake completion. The grabber reads the socket buffer and closes
    with \texttt{QUIT}.
    \item \textbf{Active Services (e.g., HTTP):} Web servers require a protocol stimulus before
    responding. The grabber establishes the connection, transmits a minimal RFC-compliant probe
    (\texttt{HEAD / HTTP/1.0\textbackslash r\textbackslash n\textbackslash r\textbackslash n}), and
    parses the \texttt{Server:} header.
\end{itemize}

\subsection{Phase 4: Dynamic OS-Aware Payload Selection Methodology}
Off-the-shelf exploitation scripts typically rely on hardcoded operating system assumptions. In our
architecture, Phase~4 bridges reconnaissance and exploitation: the system queries the Phase~3 OS
verdict and automatically injects OS-targeted parameters into all subsequent exploit modules:
\begin{itemize}
    \item \textbf{Windows Verdict:} Selects sensitive targets \texttt{windows\textbackslash win.ini}
    and \texttt{windows\textbackslash system.ini}; commands use Windows syntax (\texttt{whoami}).
    \item \textbf{Linux / POSIX Verdict:} Selects sensitive targets \texttt{/etc/passwd} and
    \texttt{/etc/shadow}; commands use Unix syntax (\texttt{id}).
\end{itemize}

\subsection{Phase 5: Targeted Exploit Methodologies \& Empirical Validation}

\subsubsection{1. FTP Exploit Suite (3 Distinct Attack Vectors)}
The FTP exploit suite implements three concrete attack techniques:
\begin{enumerate}
    \item \textbf{FTP Anonymous Access:} Connects to port~21 using RFC~959 credentials
    (\texttt{anonymous} / \texttt{anon@lab}), requests passive data mode (\texttt{PASV}), and
    retrieves root directory contents via \texttt{LIST}.
    \item \textbf{FTP Write $\rightarrow$ Web Shell $\rightarrow$ HTTP CGI RCE:} Validates write
    permissions on \texttt{uploads/}, transmits a payload script (\texttt{shell.py}) via
    \texttt{STOR}, issues an HTTP request (\texttt{GET /uploads/shell.py?cmd=<os\_cmd>}) to execute
    the payload under the web server's CGI sandbox, captures command execution output, and
    immediately cleans up forensic traces via \texttt{DELE shell.py}.
    \item \textbf{FTP Bounce Attack Pivot (RFC 959 \texttt{PORT}) — Mitigation Analysis:}
    Attempts to abuse the FTP \texttt{PORT} command to relay a TCP connection to an internal service
    port (\texttt{192.168.0.116:80}). In our experiments, this attack \hl{consistently failed with
    \texttt{[WinError 10053]}}. This negative result is analytically valuable: modern Windows kernel
    stacks and Windows Filtering Platform (WFP) explicitly detect and abort unauthorized
    third-party \texttt{PORT} socket redirection, confirming effective host-level mitigation.
\end{enumerate}

\subsubsection{3. SSH Weak-Credential Brute-Force \& Post-Exploitation Showcase}
The SSH exploit targets port~22 using a bounded dictionary of 20 high-probability enterprise
credentials. Protocol key-exchange and encrypted session negotiation are handled via \texttt{paramiko}
due to cryptography complexity, but the brute-force dispatch, rate limiting, and multi-modal
post-exploitation routines are self-authored:
\begin{itemize}
    \item \textbf{Quiet Mode (Stealth Reconnaissance):} Dispatches non-destructive audit commands
    (\texttt{whoami}, \texttt{hostname}, \texttt{ipconfig}, \texttt{ver}) without modifying the file
    system or alerting the user.
    \item \textbf{Loud Mode (Multi-Modal Proof of Compromise):} Upon authentication as
    \texttt{test:test123} on attempt 15/20, the engine deploys three interactive artefacts to the
    victim's desktop and triggers a speech synthesizer alert:
    \begin{enumerate}
        \item \textbf{Trophy File (\texttt{PROOF\_OF\_ACCESS.txt}):} Placed directly on the victim's
        Desktop, recording hostname, user account, timestamp, and RCE confirmation text.
        \item \textbf{Remote Script (\texttt{hacked.py}):} Python payload script capable of being
        executed from the remote console.
        \item \textbf{Interactive Attack Window (\texttt{HACKED.bat} / \texttt{HACKED.exe}):} Compiled
        natively via Windows \texttt{csc.exe} and deployed to Desktop. When launched, it displays a
        neon-green matrix console running an automated 1000-iteration compromise loop.
        \item \textbf{Physical Audio Alert:} Invokes Windows \texttt{System.Speech.Synthesis} to vocalize
        an audible warning on the victim PC speakers.
    \end{enumerate}
\end{itemize}
