\section{Introduction \& Recap of the Design}

\subsection{The attack and its objective}
Network reconnaissance is the opening move of any intrusion: before an attacker can act,
they must learn which services a target exposes, what software versions run there, and
which operating system underpins them. Project~\#8 asks us to build exactly this
capability — \emph{port scanning with OS information / version} — and to do so entirely
from scratch, crafting every frame, packet, and segment in our own code.

Our toolkit realises a full reconnaissance-to-exploitation chain in five phases —
(1)~raw TCP~SYN port scanning, (2)~service banner grabbing, (3)~probabilistic OS
fingerprinting, (4)~OS-aware payload selection, and (5)~a dynamic exploit battery —
paired with (6)~a defensive detector that recognises the scan and can quarantine the
attacker in real time.

\subsection{What changed since the Design Report}
The week-11 Design Report proposed a solid but comparatively modest system. During
implementation the project grew well beyond that proposal along three independent axes.
This report is organised around that growth: each core section contrasts the
\emph{originally designed} behaviour with the \emph{delivered} implementation. The table
below is the map.

\subsection{Lab topology}
The verification testbed is a single isolated private LAN. The attacker is a Windows~11
laptop running the toolkit over an Npcap adapter; the primary victim is a Windows~11
desktop hosting the vulnerable lab services; and a set of secondary targets on the same
subnet exercises the fingerprinting engine against genuinely different TCP/IP stacks.
