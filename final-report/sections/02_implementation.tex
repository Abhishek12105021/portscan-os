\subsection{The from-scratch packet layer}
The project rule is absolute: we must craft our own frame, packet, and segment. The
\texttt{common/packet.py} module does this byte-by-byte. A SYN probe is assembled as a
14-byte Ethernet header, a 20-byte IPv4 header, and a 20-byte TCP header plus options,
with both the IPv4 header checksum and the TCP checksum (computed over the 12-byte IPv4
pseudo-header) produced by our own RFC~1071 one's-complement routine. Npcap only moves
the finished bytes onto and off the wire; it makes no decision about what to send or how
to interpret a reply.

Because a half-open SYN scan operates below the OS socket layer, the toolkit must resolve
its own link-layer details. \texttt{npcap.py} obtains the outbound interface and local MAC
through the Windows IP~Helper API (\texttt{GetAdaptersInfo}) and resolves the target's MAC
with \texttt{SendARP}, falling back to the ARP cache when a reply is missed. This is what
lets us emit a complete Ethernet frame rather than relying on the kernel to fill it in.

\begin{keypoint}[Why ``our own code'' matters here]
Every discriminating fingerprint feature — TTL, window, option order, IP-ID behaviour —
is read from bytes \emph{we} parsed out of the raw response. Nothing is delegated to a
library that could normalise or hide those fields. The correctness of the packet layer is
therefore the foundation the entire fingerprinting engine stands on, and it is covered
directly by \texttt{test\_packet.py}.
\end{keypoint}

\subsection{Operational safety rails}\label{sec:safety}
The scanner is deliberately bounded so it cannot become a denial-of-service tool:

\begin{itemize}
\item \textbf{Private-only targeting.} Targets are validated with \texttt{ipaddress}; any
non-RFC-1918 address is refused.
\item \textbf{Bounded probing.} A hard \texttt{MAX\_PROBES~=~50} cap per run, with a
mandatory inter-probe delay, keeps traffic to reconnaissance volumes.
\item \textbf{Read-only exploits.} The FTP modules are bounded to \texttt{PWD}/\texttt{LIST}
and clean up any artefact they create; HTTP traversal is a read-only \texttt{GET}; SSH uses
a small bounded wordlist with a per-attempt delay.
\item \textbf{Reversible defense.} Firewall mitigation is opt-in (\texttt{--block}), every
injected rule carries a TTL, and all rules are removed on clean exit.
\end{itemize}
